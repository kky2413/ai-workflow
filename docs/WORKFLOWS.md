# 과제 유형별 가장 짧은 실행 흐름

**실제 README와 제공된 구조가 우선입니다.** 모든 절차·도구를 한꺼번에 실행하지 않습니다.

| 과제 | 첫 행동 | 핵심 구현 | 검증 |
| --- | --- | --- | --- |
| 데이터 분석·보고서 | 컬럼명·행 의미·단위·분자·분모 파악 | 집계·필요 시 데이터 연결 | 작은 표본 독립 검산, 원본·최종 표 대조 |
| CSV 전후 비교 | 식별 키·기간·열 구조 확인 | 추가·삭제·변경 행 계산 | 중복·누락·결과 원본 대조 |
| 웹 앱·API | 현재 프레임워크·화면·API·저장 방식 확인 | 입력→처리→저장→화면 연결 | 실제 API와 브라우저 수동 확인 |
| Python 자동화 | 입력·출력 계약 확인 | 최소 정상 기능 구현 | 정상·잘못된 입력·경계값 테스트 |
| 문서 작성 | 필수 형식·출처·수치 확인 | 요구 형식으로 결과 생성 | 다시 열어 글·표·단위·누락 확인 |

**데이터 연결:** `data_profile.py`로 구조 확인 → `join_audit.py`로 중복 키·행 증식 조사 → 필요하면 `merge_tables.py`. 수치 집계는 `quality_report.py`, 명시된 기준 검사는 `rule_check.py`를 사용합니다. 자세한 명령은 [도구 목록](TOOL_CATALOG.md)에 있습니다.

**웹:** [웹 개발 가이드](WEB_APP_PLAYBOOK.md) → [웹 검증](WEB_TESTING.md). 기존 React/Vite/Next/Node/Flask 등 프로젝트는 기존 실행 방법부터 확인합니다.

**업무 기준을 모를 때:** 임의로 합격·불합격, 요금, 우선순위, 알고리즘 제약을 정하지 않습니다. 실제 결과를 바꾸는 기준만 담당자에게 확인합니다.

**완료:** 요구사항별 **무엇을 만들었는지 + 어떤 실제 실행으로 확인했는지 + 미확인 사항**을 짧게 남깁니다. 문서 작성을 위해 기능 구현 시간을 지나치게 쓰지 마세요.
