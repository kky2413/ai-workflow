# Codex 프롬프트 — 단계별로 하나씩 사용

이 문장들은 **실제 과제의 README를 읽고** 적용하는 범용 예시입니다. 과제 전체를 준비된 저장소로 대체하지 않습니다. 필요한 프롬프트만 골라 사용하세요.

## 1. 분석 (구현 전)

~~~text
현재 작업 폴더의 실제 README와 제공 파일을 먼저 확인해 주세요.
목표, 필수 기능, 입력 자료·기존 코드, 최종 산출물 경로,
모호한 업무 기준, 완료를 판단할 검증 방법을 정리하고
우선순위별 최소 구현 계획을 제안해 주세요.
아직 코드를 수정하거나 패키지를 설치하지 마세요.
~~~

## 2. 구현 (분석 내용을 확인한 뒤)

~~~text
가장 중요한 필수 기능부터 실제 입력→처리→출력으로 완성해 주세요.
기존 코드·데이터·실행법을 보존하고 불필요한 스택 교체는 하지 마세요.
각 단계를 실제로 실행·검증하고 변경 이유, 실제 결과,
미완료·미검증 항목을 짧게 알려주세요.
기준값이 없으면 추측하지 마세요.
~~~

## 3. 웹사이트인 경우에만 추가

~~~text
현재 웹 프로젝트의 프레임워크, package.json 실행 스크립트,
화면·API·저장 방식을 확인해 주세요.
필수 사용자 행동을 화면 입력→실제 API→업무 처리·저장→
화면 갱신·새로고침까지 연결해 구현해 주세요.
API 테스트를 실행하고, 제가 브라우저에서 직접 검증할
버튼·입력·오류·반응형 확인 절차를 알려주세요.
화면을 직접 확인하지 않았다면 미검증으로 표시하세요.
~~~

## 4. 최종 검증

~~~text
실제 README의 필수 요구사항별로 구현 파일과 실행한 테스트를 대조해 주세요.
각 검증의 기대 결과·실제 결과·통과/실패/미실행 상태를 보여주세요.
정답은 구현 코드의 출력값을 그대로 복사하지 말고
작은 입력·원본 근거로 독립적으로 확인해 주세요.
남은 한계와 필수 산출물 경로도 확인해 주세요.
~~~

## 5. 업무 수행 결과 요약 및 기술 결정 기록

프로젝트 인수인계, 구현 리뷰, 유지보수에 사용할 **근거 중심 업무 요약**입니다. 설명과 실제 동작을 혼동하지 않도록 코드·설정·실행 로그를 먼저 확인합니다.

~~~text
현재 작업 폴더의 실제 README, 소스 코드, 설정, 변경 이력과
확인 가능한 실행·테스트 로그를 근거로 업무 수행 결과를 정리해 주세요.

1. 목적과 범위: 해결하려던 문제, 필수 요구사항, 실제 완료한 기능,
   산출물 파일·경로를 정리해 주세요.
2. 기술적 선택: 핵심 알고리즘 또는 구현 방식이 무엇인지,
   선택 이유, 실제 검토한 대안과 비교 기준, 포기한 장단점을 설명해 주세요.
   최적성·성능을 증명하지 않았다면 그 한계를 명시하세요.
3. 데이터와 구조: 원본 입력 → 검증·변환 → 핵심 처리·계산 →
   상태·저장 → API·화면·파일 출력의 흐름을 설명해 주세요.
   각 단계의 담당 모듈·함수와 데이터/상태 관리 위치를 구분하고,
   없는 단계는 임의로 추가하지 마세요.
4. 생성과 검증: 결과를 만드는 로직과 결과의 유효성을 검사하는
   로직을 구분해 주세요. 실제 확인한 조건, 기대값의 근거,
   실행한 명령·관찰값·통과/실패/미실행 상태를 정리해 주세요.
   제3자가 동일한 입력으로 재현할 수 있는 방법도 작성해 주세요.
5. 문제 해결: 실제 발생한 오류·원인·수정 내용과 재검증 결과,
   아직 남은 결함 또는 미확인 사항을 작성해 주세요.
6. AI 및 외부 도구 활용: 실제 작업 기록에서 AI/도구가 제안한 내용,
   이를 채택·수정·보류·거절한 사례와 판단 기준을 구분해 주세요.
   사용자가 직접 판단·확인한 사실과 AI가 수행한 작업을 혼동하지 마세요.
7. 후속 작업: 운영 시 주의점, 우선 개선 항목, 다음 담당자가
   바로 실행할 명령과 확인할 파일을 정리해 주세요.

출력은 '핵심 요약(5문장 이내) → 주요 결정과 근거 →
데이터·구성 흐름 → 검증 결과 표 → 이슈·한계 → 다음 작업' 순서로,
핵심 내용만 간결하게 작성해 주세요. 주요 주장에는 파일 경로,
함수명 또는 실제 실행 결과를 붙여 주세요.

실제로 검토하지 않은 대안을 검토했다고 쓰지 마세요.
실행하지 않은 테스트를 통과로 표시하지 말고 '미실행'으로,
확인할 수 없는 내용은 '미확인'으로, 해당 사항이 없으면
'해당 없음'으로 구분해 주세요. 로그에 없는 대화·판단을 지어내지 마세요.
~~~

**활용 예시:** 개발 완료 요약, 코드 리뷰, 기술 선택 근거 정리, 장애 분석, 후속 담당자 인수인계. AI와의 협업 사례가 기록되지 않았다면 임의로 생성하지 않습니다.

---

**기억하기:** 목적 → 선택 이유 → 실제 구조 → 검증 근거 → 문제·한계 → 후속 조치.

프로젝트의 AI 사용·자료 반출 정책을 따르고, 최종 요약은 실제 코드와 기록을 대조하여 확인하세요. 상세 절차는 [업무별 흐름](WORKFLOWS.md), [웹 개발](WEB_APP_PLAYBOOK.md), [웹 검증](WEB_TESTING.md)을 참고하세요.
