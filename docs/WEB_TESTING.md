# 웹사이트 검증: 화면·API·데이터·제출

웹 검증은 “서버가 실행됐다”가 아니라 **요구된 행동으로 기대한 결과를 얻었는지** 확인하는 과정입니다.

## 검증을 세 층으로 나누기

| 층 | 도구와 확인 대상 | 이 검사만으로 증명할 수 없는 것 |
| --- | --- | --- |
| 프로젝트 조사 | web_project_audit.py — 진입점·패키지·테스트 후보 | 실제 사이트 실행 |
| API·코드 실행 | 기존 테스트, web_api_check.py — 상태·JSON·오류·저장 | 화면이 보이고 사용 가능한지 |
| 사람의 UI 수동 확인 | 제공된 브라우저 — 버튼·폼·탐색·새로고침·반응형 | 모든 데이터·환경에서 완벽한지 |

**기존 프로젝트의 README와 package.json 스크립트를 먼저 확인하세요.** npm run으로 실제 실행 가능한 스크립트를 조회할 수 있습니다.

## 로컬 API 검사

Python이 있는 경우에만 로컬 서버를 실제로 실행한 다음 다음 검사를 사용할 수 있습니다.

~~~sh
python3 scripts/web_api_check.py --config demo-web/api-check.example.json
~~~

설정 예시 (실제 과제에 맞춰 경로·기대값을 바꿔야 합니다):

~~~json
{
  "base_url": "http://127.0.0.1:3000",
  "cases": [
    {"name":"health","method":"GET","path":"/api/health","expect_status":200,"expect_json":{"status":"ok"}},
    {"name":"list","method":"GET","path":"/api/items","expect_status":200,"expect_json_fields":["items"]}
  ]
}
~~~

- expect_json은 **객체의 명시된 필드만 부분 비교**, 배열과 원시값은 정확히 비교합니다.
- 기본적으로 GET/HEAD만 호출합니다. 데이터 변경 요청은 --allow-writes 옵션을 사용자가 명시해야 합니다.
- HTTP 외부 호스트·HTTPS·리다이렉트 추적·프록시 접근을 허용하지 않습니다.
- **테스트 0개는 성공으로 처리하지 않습니다.** 0=검사 통과, 1=검사 실패, 2=설정/실행 오류.
- HTTP/JSON 구조 검사만으로 실제 비즈니스 계산이나 화면 품질을 증명하지 않습니다.

Node 연습 앱 테스트는 demo-web 폴더에서 다음과 같이 실행합니다.

~~~sh
npm test
npm run dev
~~~

기존 React/Vite/Next 웹 프로젝트는 실제 package.json scripts에 있는 test/build/dev 명령을 사용하세요. 없는 스크립트를 임의로 가정하지 마세요.

## 직접 브라우저에서 확인할 핵심 행동

| 행동 | 기대 결과 |
| --- | --- |
| 실제 주소와 포트 열기 | 제목·목록·입력이 표시됨 |
| 항목 정상 입력·저장 | 실제 서버 처리 후 화면에 반영 |
| 수정·삭제·상태 변경 | 다른 항목은 보존되고 요청한 항목만 변경 |
| 새로고침·서버 재시작 | 요구된 상태 유지·저장 동작 확인 |
| 빈 값·잘못된 값 | 저장 거부와 이해 가능한 오류 표시 |
| 검색·필터 | 원본 항목과 표시 결과 일치 |
| 모바일 폭·키보드 | 버튼이 잘리지 않고 주요 동작 접근 가능 |
| 서버/API 장애 | 무한 로딩 또는 가짜 성공 대신 오류 표시 |

**사람이 직접 조작하지 않은 화면은 “수동 검증 완료”로 표시하지 마세요.** 플랫폼에서 허용하지 않는 Computer Use·Playwright·Selenium 자동 조작은 하지 않습니다.

## 검증 결과 기록

| 요구사항 | 실제 실행 명령/사용자 행동 | 기대값 | 관찰값 | 판정 |
| --- | --- | --- | --- | --- |
| API 응답 | GET /api/items | items 배열 | 실제 실행 내용 | 통과/실패/미검증 |
| 상태 유지 | 저장 후 새로고침 | 저장된 항목 유지 | 실제 화면 관찰 | 통과/실패/미검증 |
| 빌드 | npm run build (스크립트가 있다면) | 종료 0 | 실제 로그 | 통과/실패/미검증 |

테스트 결과는 **검사가 실행된 당시 코드**의 증거입니다. 코드를 수정했다면 관련 테스트를 다시 실행해야 합니다.
