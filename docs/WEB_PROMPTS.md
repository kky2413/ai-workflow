# 웹사이트 제작용 Codex 요청문

각 문장은 Codex 입력창에서 사용합니다. 실제 과제의 허용 범위 내에서 필요한 요청만 선택하세요.

## 1. 실제 웹 프로젝트 분석

> 현재 과제 README와 제공 파일을 우선 확인해 주세요. 사용자·필수 화면·행동, 현재 프레임워크와 package.json scripts, 서버 엔트리와 API, 데이터 저장 방식, 제출 경로, 모호한 업무 기준을 구분해 주세요. 실제 입력→서버 처리/저장→화면 결과로 연결되는 최소 기능을 제안하고, 아직 코드나 설정을 바꾸지 마세요.

## 2. 처음부터 사이트 구현

> 필수 기능 하나를 화면 입력→실제 서버/API→업무 처리→저장→다시 조회→화면 갱신까지 작동하게 만드세요. 실제 자료·업무 규칙을 확인하고, 하드코딩된 결과나 가짜 성공 메시지를 사용하지 마세요. 제공된 스택과 구조를 유지하고, 필요한 파일만 수정하세요. 실제 실행 명령과 테스트 결과를 보여준 뒤 제가 미리보기에서 직접 검증할 행동 3~5개를 알려주세요.

## 3. 기존 사이트 오류 수정

> 실제 오류 로그, 실패하는 UI 행동, 관련 API 응답을 먼저 확인하고 문제를 재현해 주세요. 원인을 하나씩 좁히고 가장 적은 파일만 수정하세요. 동일한 입력으로 수정 후 결과를 재확인하고, 기존 정상 기능도 테스트해 주세요. 패키지 무단 설치·외부 서버 연결·보안 제한 우회는 하지 마세요.

## 4. 제출 전 웹 검증

> README 필수 요구사항마다 구현 파일, 실제 테스트 명령, 기대값, 관찰값, 미검증 항목을 표로 보여주세요. 서버·API와 정상/오류 입력을 실제 실행하여 검증하세요. 화면 자동 조작을 대신하지 말고 제가 직접 확인할 화면·버튼·입력·새로고침 순서를 알려주세요. 제가 확인했다고 보고하기 전에는 UI 검증 상태를 “미확인”으로 두세요. 제출 파일·경로·더미/비밀값도 확인해 주세요.

## 5. 내가 설명할 수 있도록

> 실제 작성된 코드와 실행 로그만 근거로 **무엇을·왜·어떻게·검증·한계**를 정리해 주세요. 입력에서 API·처리·저장·화면으로 이어지는 흐름과 실제로 고친 버그를 구분하고, 제가 이해한 내용을 확인할 질문 세 개를 해 주세요.
